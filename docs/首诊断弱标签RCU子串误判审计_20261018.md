# 首诊断弱标签规则审计：circular误命中rcu

2026-10-18制作新讲解Slide时发现。此审计只读取公开冻结元数据和已导出的生成代码，未调用模型、未访问私有日志，未修改旧标签或历史分数。

## 可复现原因

`research/jev-qwen35-9b-20261016/prepare-data.py`的`annotation()`先判断`elif 'rcu' in sig`，之后才判断`circular locking`。但：

```python
'rcu' in 'possible circular locking dependency'  # True
```

原因是`circular = ci + rcu + lar`。因此循环锁依赖标记会先进入`rcu_progress`分支。

## 对既有结论的影响

原66/87与78/87是对现有弱标签的吻合，包含此缺陷；不代表独立专家诊断真值。四条RCU标签有问题，也意味着原RCU逐类支持数与逐类成绩需要在新版本复核。不能只修改这四条就宣布其余标签全部正确，也不能在未完整重评前宣称修正后的准确率。

该问题位于9B分类数据的标签构造，不证明27B性能时间或PPLX独立实验受同一代码影响，也不影响它们已经记录的时间戳真实性。不同研究的标签流程需要分别审计。

## 修复与研究政策

冻结历史代码、数据、分数保留。下一轮可优先识别明确locking标记，并将RCU判断限定为明确`rcu:`、`INFO: rcu_`等边界匹配；不能再用无边界子串。具体规则须覆盖真实日志并由人工复核，至少补充“circular不触发RCU”和真实RCU正例回归检查。
