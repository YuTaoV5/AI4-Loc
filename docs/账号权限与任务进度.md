# 账号、专家交互与任务状态

首次启动自动创建 `admin / admin` 管理员账号。用户注册后默认为测试人员；专家、领导及管理员身份由管理员在账号管理页面设置。密码使用随机盐及 scrypt 哈希，服务端保存会话令牌的 SHA256。浏览器采用 HttpOnly、SameSite=Strict 会话 Cookie，提供登录、注册、退出及显示名称编辑。管理员审核与合入权限由已登录账号决定，旧管理员密钥不再授予权限。

日志任务、社区试跑、Skill 投稿和 Skill 跑分历史绑定用户 ID。个人记录可以在其他浏览器登录同一账号后查看。普通账号不能读取或审核其他账号的任务，也不能读取其原始日志、导出报告或进度流。管理员可访问工作区任务，并显式关联未绑定账号的历史本地记录。当前浏览器的旧个人标识在登录后迁移到账号，已关联其他账号的任务不会再次迁移。

前三名专家卡片悬停旋转，背面显示已解决问题、Skill 调用次数与 Benchmark F1。点击首席卡片生成 30 个彩色粒子的短暂烟花，不依赖外部动画库；点击或键盘 Enter/空格亦可翻转。尊重系统减少动画设置。当前没有已合入贡献者时，卡片明确显示空席位和缺失数据。

个人空间点击任务名称或「展开分析进度」，在任务下展开阶段时间轴：

1. 任务排队。
2. 读取及校验日志；上传归档先读取、解压。
3. 提取异常特征、内核版本与调用链。
4. 匹配选定 Skill 和社区修复案例。
5. 解析源码版本，提交下载或复用缓存；源码下载本身独立运行。
6. 生成带证据与贡献者署名的定位报告。
7. 分析完成，等待人工验证；异常时记录失败状态与原因。

每个阶段保存开始、结束时间及执行消息。`GET /api/jobs/:id/progress` 返回快照，`GET /api/jobs/:id/events` 通过 SSE 推送状态及完整时间轴，刷新或重连可恢复历史进度。任务结束后前端关闭实时订阅，源码缓存仍通过工作区状态刷新展示。旧任务没有阶段记录时会明确标记，不制造历史时间轴。

当前执行器仍为规则分析引擎，未连接 LLM Agent。页面显示的是可观察的执行阶段、消息、失败原因与工具任务状态，不展示模型内部推理。后续接入 Agent 时，应在真实调度/工具执行/报告生成事件中调用 `server/task-progress.js` 的 `step` / `settle`，复用同一用户界面和权限检查。
