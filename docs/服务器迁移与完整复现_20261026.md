### 3.1 本机私有文件（禁止提交 Git）

用户电脑目录：

加密格式为本项目 `scripts/migration-archive.py` 的流式 AES-256-GCM，头 `AI4LOC-PRIVATE-v1\n`、12 字节 nonce、密文、末尾 16 字节 tag。头也参与认证。解密使用临时输出，只有认证成功才重命名；认证失败不得使用输出。使用同一密钥但不同随机 nonce 加密核心包和完整包。

核心包已在本机通过解密认证，原始 tar SHA256：

```text
d42a3cc2701dd65fab2f2b14d708cf8bc0751db5422fcf14d0b6070834833ef8
```

具体大小、密文 hash 和完整包 hash 记录在本机 manifest 及最终迁移验收记录，不从本文猜测。

### 3.2 两个包的恢复层级

**core** tar 顶层为 `kernel-insight/`，另有 `platform/root-bootstrap.sh`，包含：

- `supervisord.conf`、`verified-source-registry.json`。
- `services/minimax/credentials.json`（含真实上游凭据，因此整包必须私下传递）。
- `data/state.json`：任务、Skill、审核/评测状态和个人组合等。
- `data/accounts.json`：账号、密码哈希、角色和会话；不能用空数据启动后新建账号替代原归属关系。
- `data/skill-pulls`：封存原包、内容、逐文件 hash、审核/Benchmark 证据。
- `data/harness-home`：已发布的公共 Skill 目录。
- `data/reports`：生产报告。社区六例在 Git 跟踪的 `release/data/benchmark`，不是私有 `/opt/kernel-insight/data/benchmark`；源码恢复时一并带回。
- 原容器 `/root/bootstrap.sh` 的备份副本；不要不检查就覆盖新平台自己的启动脚本。

**bulk** tar 顶层为 `runtime/` 和 `data/`，含 Node / npm / venv / SDK runtime、历史任务工作区、输入材料、手机语料、冻结定位数据集、源码缓存和验收证据。归档时有意排除：

- `*/dsh-home/profiles`：每个任务重复生成的 SDK profile 缓存，首次运行会由同版本 runtime 重新物化。
- ABRLog `download-parts` 与未完成 `.part`。
- `data/npm-cache`、`data/backups`、数据根下 PID 文件。

这些排除不应删掉 `dsh-home/skills`、`input`、`source-context`、原始 Skill 封存包或冻结构建产物。代码从 Git 获取，bulk 不替代 GitHub 源码。

**关键陷阱：只复制公共 `harness-home/skills` 不够。** `server/skill-packages.js` 在任务暂存时仍要验证 `skill-pulls/<id>/package/original`、`files.json` 和完整展开内容。恢复必须同时保留 state、封存私有包和公共目录，否则已启用 Skill 会在运行前报指纹/文件不存在。

### 3.3 在新机器解密（先校验后解压）

将两个 `.aes` 和密钥通过私有渠道放到新服务器 root 私有目录，例如 `/root/ai4loc-migration`，目录 0700，密钥 0600。以下操作不需要旧服务器在线：


### 4.2 新服务器必须调整的机器相关字段

- SSH 地址/端口和客户端转发对象。
- OS 的 user namespace / bubblewrap 可用性。需要服务账号运行隔离，不能为图省事回退无沙箱模型执行。
- `KERNEL_BENCHMARK_HARDWARE_ID`：旧值残留 A100/Ollama/SGLang 历史描述，不代表当前 MiniMax 外部 API 的硬件配置。新机器应改成真实部署标识，例如 `external-minimax-chat/<new-host-id>`；cohort 会变化，旧榜分不能直接冒充同环境成绩。
- 若换绝对根目录，要同步调整 venv、Supervisor、source registry、数据 manifest、沙箱路径和历史可迁移路径；本交接推荐不换根目录。
- 对外访问仍用 SSH 转发；不要将 11436 网关监听公网以取代 SSH。

已恢复的 root-private credentials 可以直接使用；如用户更换 provider Key，只通过私有文件更新并单独重启网关。配置文件结构：

```json

```

网关仅允许官方 `.cn/v1` 或 `.io/v1` 端点。不打印文件内容，不把真实 Key 复制成 `KERNEL_AGENT_API_KEY`。服务账号无权读 root 私有凭据，正是预期隔离。

- 日志：`data/web.stdout.log`、`web.stderr.log`、`minimax.stdout.log`、`minimax.stderr.log`，每次工作区 `dsh-trace.jsonl`、`request.json`、SDK session 和报告。原始会话可能含用户材料，不公开上传。
- 项目维护：`runtime/venv/bin/python app/scripts/manage-supervisor.py --restart`；脚本会拒绝运行中的任务/Agent benchmark/Skill 测试，不要直接 kill 全机模型进程绕过保护。

- EACCES：确认服务账号对 data 和工作区有写权，脚本可执行，root credential 仍不可读。Windows tar 上传可丢执行位。
- bad interpreter / `\r`：对 shell 脚本转 LF，chmod 755。
- `node` 找不到 npm：本环境 `runtime/node runtime/npm/bin/npm-cli.js`；不要假设 npm 在 PATH 中是可执行文件。
- native Skill 不见：检查已合入/published、原包指纹、选中快照、nativeSkills、任务 `dsh-home/skills`、SDK patch 插件；不要简单扫描 root 的全局 ~/.dsh。
- Key 401/模型不见：先检查 root 网关配置及允许的官方 baseUrl；不把 Key 下发给 Agent 修复。
- 报告超时/Token 截断：保留失败和 finish_reason；调整后按相同套件重测，不把残缺报告计作成功。网站完整测试与 Harness 独立预算不同。
- 评分难匹配：根因自由文本不做全字符串比较；手机受控集采用限定阶段/组件/机制+可核对证据+动作。真实包没有金标准就不计算根因准确率。
- 端口 8788 空响应：先 `curl.exe http://127.0.0.1:8788/api/health`，再检查 SSH 隧道；旧服务器重启后旧 tunnel 进程可存活但连接已断。
