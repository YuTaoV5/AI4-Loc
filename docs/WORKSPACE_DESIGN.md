# Kernel Insight 工作空间重构

## 本次已实现

- 新建分析页采用单输入区：粘贴日志、添加附件、提交。可拖拽文件，多文件与文本可以同时提交。Skill、机器、版本、commit、源码下载收进分析选项。
- 从分析入口移除任务队列。提交后显示轻量回执，通过个人空间查看进度和报告。
- 个人空间归集本地个人标识的日志任务、社区案例试跑、Skill Benchmark 跑分历史、Skill 投稿；可编辑显示名称、搜索及筛选任务。
- 新任务及跑分在后端保存归属。当前浏览器持有的旧 Skill 投稿凭据经校验后自动关联；旧任务身份未知，保留在明确标记的历史本地记录中。
- 社区试跑保持分类和页面位置，在案例卡片显示结果。查看报告仍留在 Benchmark 路径，返回恢复案例页面。
- 主导航采用新建分析、个人空间、效能看板、专家中心、社区 Benchmark。辅助导航（Skill 合入、源码、帮助）固定在左下角，以图标、提示文字及无障碍标签展示。
- 个人空间及上下文报告支持页面地址与浏览器返回。现已通过账号及会话实现跨浏览器个人归属与任务访问检查，具体实现见 ACCOUNTS_AND_PROGRESS.md。

## 三类用户的后续改进建议

| 视角 | 最重要的决策 | 建议优先改进 | 需要的数据或条件 |
| --- | --- | --- | --- |
| 领导 | 是否持续缩短定位周期、哪些风险未解决 | 时间范围/团队筛选、P50/P90 耗时、超期与高风险问题、样本量与基线可信度，指标可钻取到证据 | 团队、严重度、关闭时间、人工基线与验证记录 |
| 专家 | 我的知识帮到了谁，下一步补什么 | 待改进案例收件箱、测试失败差异、Skill 版本对比与覆盖缺口；贡献榜同时呈现持续贡献，减少使用量对冷门领域的压制 | Skill 版本快照、细分类别分布、采纳及退回原因、合并归因规则 |
| 测试人员 | 这批日志哪些必须马上处理 | 同签名异常聚类、批次归组、失败重试、上次 Skill 组合记忆、键盘提交与筛选，接入压测流水线 | 机器/批次标识、稳定签名、幂等任务接口与流水线鉴权 |

建议顺序：先把批次归组和失败重试做好，再扩充固定 Benchmark 与专家改进反馈，最后引入团队维度和领导看板钻取。后续可进一步接入企业 SSO 和生产数据库；本地标识向账号身份的迁移已实现。

本次页面聚焦「提交一个新问题」与「查看我的历史」两个清晰入口。建议项尚未实现，不应在产品中显示推测数据或虚构能力。
