# Linux 稳定性工作台实施状态

当前运行说明、数据来源、评估口径与边界以仓库根目录 [README.md](../README.md) 为准。

已将移动端固定示例原型替换为 Linux 日志工作台，移除固定结论与固定分数的后端逻辑。

## 已实现

1. 六个真实社区案例的完整原始 crash report、根因摘要、修复依据、版本与源码 commit 元数据，提供可重复采集脚本。
2. 自动源码获取：官方发布版、Mainline / Stable / Linux-next commit；SHA256、解压、持久化缓存、状态和重试。
3. 领导效能看板：真实任务闭环、相似问题归并、配对人工基线提升率、趋势和分布。
4. 专家 Skill 中心：规则/建议登记、贡献者署名、测试集类别评估、启用门禁、使用和反馈统计。
5. 测试工作台：批量文本/压缩日志、粘贴日志、版本识别、证据/调用链、社区候选根因、审核、报告导出。
6. 前端脱离外部 CDN，支持桌面与窄屏；任务、审核和 Skill 持久化。

## 尚未完成的生产能力

- 已用 syzbot.org 获取完整 crash report；源码下载机制通过模拟上游响应测试并实际获取 Linux 6.6 官方源码。
- 目前仅规则分诊与知识检索，未接入 LLM、源码自动推理、自动复现或根因证明。
- 数据集需扩大，并增加完整 console log、config、复现器、补丁全文及独立根因审核。
- 多用户登录、权限、管理员审核、审计、数据库、任务调度和生产部署尚未接入。
- 当前 Skill 评估为类别检索；根因定位评估需要单独定义金标准和严格隐藏测试集，不能用试跑命中率替代。

## 后续接入顺序

先打通外网/内部镜像并完成数据采集，再增加源码与补丁证据校验和专家根因金标准，然后接入分析 worker 与复现评估，最后接入多用户权限、数据库和生产运维。
