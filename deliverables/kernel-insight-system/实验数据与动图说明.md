## 怎么看

双击 `deck.html` 离线打开，输入49跳到新增章节。第50、51、52、54、55页是五组实测回放；第56页下拉菜单覆盖主实验全部8种工作量／缓存组合。P播放暂停，J/K按结果事件走步，也可拖动时间轴、切换速度或直接到结束。默认停在起点，离页自动暂停。

每组两边都是**同一repeat编号的两个独立trial**，把同步放行的任务起点对齐为t=0；没有让两个模型同时占用显卡，没有对较慢的一边单独加速。五次均值和单次回放各自标注。联合代表重复的选择规则：找出两端各自整批完成时间中位数，选两端“与各自中位数的相对距离之和”最小的共同repeat。不是挑最佳一次，也不平均轨迹。

## 图中每一项是什么

| 显示 | 数据来源与定义 | 不能据此推出 |
|---|---|---|
| 用户结果数 | Decision在完整概率HTTP返回时结算；Chat在首个非空content到达时结算 | Decision有文本TTFT；batch8第一个内部问题完成就已返回全部概率 |
| 已返回文本token | 成功HTTP的usage.completion_tokens在结果可用时结算；本轮Decision为0，Chat每请求1 | Decision没有prefill、没有状态或没有计算 |
| 活跃attention KV曲线 | 每个调度边界full_num_used × 64KiB，以MiB显示；观测间保持最近值 | 连续GPU时间上的精确占用，或整个预分配池已经释放 |
| 线性状态槽 | mamba_num_used；32个状态槽池中被标为活跃的槽 | 32个token；可与KV token数量直接相加 |
| 未命中token | 每个内部请求prompt_tokens−cached_tokens，在原生prefill_finished_time结算 | 唯一token数、真实FLOPs、所有replay工作量、连续逐tokenGPU进度 |
| 复用token | cached_tokens同样在prefill完成时结算；按请求求和 | 执行过prime就保证命中，或相同题干8题只prefill一次 |
| 累计结算速率 | 已完成prefill的未命中token总数 / min(t,该trial整批完成时间)；0时刻未定义 | 纯kernel吞吐、瞬时GPU token/s、生成token/s |
| HTTP横条与黑点 | 浅灰为整个请求起止范围；有色为回放到当前的在途部分；黑点为结果可用 | 浅灰区间一定在GPU计算，或并发4就一定获得4倍吞吐 |
| 整卡NVML | 最近一次实际NVML显存used值，采样约100ms | 每次绘制都重新观测，或两次采样之间不存在峰值 |
| 5次均值 | 各配置5个trial的整批完成时间均值 | 正在播放的是均值轨迹，或技术重复相当于独立故障 |

第一个调度快照之前KV与状态显示“—”，不虚构初始0；某端先结束后保持最后实际观测，不模拟后续资源变化。为便于对照，两边使用相同秒尺、KV纵轴和token条长度比例。token数是离散结算，不做平滑插值。

KV换算来自实际配置：2(K/V)×16(full-attention层)×4(KV heads)×256(head dim)×2(BF16 bytes)=65536 bytes/token。48个linear-attention层的状态另列。NVML整卡used、CUDA allocated/reserved、活跃KV、可回收KV和固定池容量是不同指标，完整数据均有保留。

## 实验和结论的边界

主实验80 trial：接口2种 × 并发1/4 × 每任务1/8步 × 冷/预热 × 5重复；另20个batch8 trial、12个额外观测开销对照，总112。正式980 HTTP对应1330个内部问题；所有问题均唯一关联客户端调用与服务端元数据，465对完整prompt token SHA相同。

任务内日志和问题题干固定，选项集合／顺序不同；4任务使用4个既有故障日志窗口。Chat关闭thinking、max_tokens=1，Decision读取五项标签概率。冷条件每trial开始flush，之后任务内允许复用；预热条件另用不同选项prime。125个prime、2个接口预热不计入正式时间，4个prompt对齐预检与SGLang启动请求单列。

四任务八步预热条件，Decision/Chat平均trial峰值活跃KV为916.438/916.250MiB、活跃linear状态16/13槽，不支持Decision节省内存。原服务配置4但实际被9槽池限制为1；正式实例32槽、静态比例0.78，实际容量和调度批次4；测试结束生产恢复原0.70/auto9配置。这是通用Qwen3.8的有限决策接口，不能混同PPLX专用权重。

这轮不计算根因准确率，不是完整Agent、长篇Chat或thinking开启的速度对照。4个固定输入、单A100、loopback、5次技术重复限制泛化。原配置启动区段校准另存，不与正式故障窗口混合；两轮输入和内存预算不同，不构成单因素扩池消融。

- [animation-data.json](media/kv/animation-data.json)：十组回放所需的原始观测子集、trial/repeat选择、每次请求与prefill记录；嵌入deck的JSON与此文件一致。
