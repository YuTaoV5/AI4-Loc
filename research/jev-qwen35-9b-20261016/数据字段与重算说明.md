# 数据字段与重算说明

本轮有三种独立实验，不要合并分母：8k上下文接口性能、第一诊断弱标签分类、32k上下文完整Agent。基座与训练后模型另有各自目录。

## 公开文件

| 文件 | 含义与单位 |
| --- | --- |
| `data/<模型>/protocol.json` | 开始前冻结的112-trial调度、输入窗口SHA、选项、seed、缓存定义、代码指纹 |
| `calls.jsonl` | 每HTTP的主机wall/monotonic纳秒、headers/首body/首Chat内容/结束时间、usage、状态；formal `trial>=0`，warmup为-1，prime为-2 |
| `answers-and-arrivals.jsonl` | 完整候选概率、选择及每段body/SSE抵达时间；无原日志、原prompt和可逆prompt token IDs |
| `server-requests.jsonl` | SGLang内部问题的排队/prefill/调度/响应计时、cache命中、原生ID与客户端rid；准确率请求标为trial=-3 |
| `scheduler.jsonl.gz` | 每次run_batch/process_batch_result前后的队列、请求、KV/linear状态与torch allocator；主机wall/mono纳秒 |
| `prometheus.jsonl.gz` | 约50ms加HTTP开销采样的原生gauges；gauges按调度更新，不能解释成同步查询GPU物理分配器 |
| `gpu.csv` | NVML约100ms：时间戳、used/free MiB、GPU/显存利用率%、温度℃、power W、SM/显存时钟MHz；服务器时区+0800 |
| `accuracy.jsonl` | 每个测试案例3种固定选项置换×2API的完整概率/预测/usage/真实Chat首内容/时长；gold只由评估器评分使用 |

## 时间与关联

Decision没有文本TTFT。主指标 `seconds` 是HTTP开始至完整JSON解析/校验完成；`decision_last_probability_body_seconds` 是最后body片段抵达，不包含之后校验开销，两者都保留。Chat的 `ttft_seconds` 来自首个非空 `delta.content`，不是headers、role、reasoning或结束SSE；非空空白字符串也计入，原始SSE保留可重算其他口径。

原生请求按完整prompt token SHA＋服务端接收时间关联：优先严格客户端时间区间，零候选才允许±2ms；每条必须唯一。相邻Decision与Chat使用相同prompt，若一开始就放宽2ms，会把相邻请求错误地判作歧义；导出器已改成严格区间优先，保留首次导出失败记录。所有2660个正式内部问题和1044个准确率内部请求均唯一关联。

`queue_time`及各原生`*_ts/time`为秒，`prefill_finished_time-forward_entry_time`为主机prefill区间，不是CUDA纯kernel时长。队列/CPU提交、GPU异步执行与网络接收不必严格相加，不能将差值强行命名为某个未测阶段。调度hook没有插入CUDA同步，host边界不等于GPU执行完成边界。

跨时钟对齐用同一HTTP的 `(start_wall_ns,start_mono_ns)`：trial的wall起点为 `start_wall_ns-(start_mono_ns-trial_start_mono_ns)`。NVML换算至同一trial时间轴；两API的独立trial用共同放行点对齐，不代表同时占用GPU。毫秒级时钟观测与100ms采样不能推断微秒级显存或功耗峰值。

## 内存与能量

9B为32层混合注意力，8层full、24层linear。全注意力KV：`2(K/V)*8*4(KV头)*256(维)*2(BF16字节)=32768 bytes/token`。`full_num_used`乘该值才是活跃attention KV；`full_evictable_size`是可回收缓存；linear状态按独立槽数报告。预分配池容量、resident NVML显存、torch allocated/reserved/lifetime peak不互相替代，不能直接相加。

`trial-power-energy.csv` 用trial内实际NVML样本做梯形积分，记录实际覆盖秒数，少于两个样本为空值而非零；不外推未观测首尾、不减假设idle功耗，也不将并发任务每个分摊整段能量。该数是部分窗口GPU板级能量，不是完整请求独占或纯推理能耗。

## 统计与限制

性能每格5次运行重复，固定4段输入；置信区间是配对repeat bootstrap，不能推广到所有日志/服务器。分类使用87案例、20机制簇，3种选项置换不是新增独立样本；跨内核同机制仍相关。机制聚类bootstrap仅探索。开发集4例，弱标签和历史test已见是主要限制。

LoRA训练只监督family choice，未训练stage/reporter/owner/noul/score。混合流程接口可返回这些问题的结果，并不证明这些能力已提升。训练后的条件概率NLL恶化、温度0.5使测试更差，详见报告；实际错误不可用训练loss近零或ECE改善掩盖。

完整Agent最初因8k输入过长失败，首次32k又暴露`tool_calls:null`解析错误。两轮失败与受控停止保留；最终32k修复轮独立保存，两个模型使用相同客户端修复。性能8k与完整流程32k不作混杂因果消融。
